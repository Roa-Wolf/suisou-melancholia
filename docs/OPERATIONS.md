# 制作・運用方針

## 正本

GitHubリポジトリ `Roa-Wolf/suisou-melancholia` を唯一の正本とします。

- 公開元：GitHub Pages
- 公開ドメイン：`suisoumelancholia.jp`
- 公開ブランチ：`main`
- ローカル作業場所：`/Users/fujimuramika/Documents/Codex/Projects/suisou-melancholia`

ChatGPTのプロジェクトは企画と文脈の保管場所、Codexのローカルプロジェクトは実装と検証の場所です。どちらで作業しても、確定した変更はGitHubへ集約します。

## 作業開始

```bash
git status
git fetch origin
git pull --ff-only
```

未保存変更がある場合は、pullする前に内容と作業者を確認します。別経路で同じファイルを同時に編集しません。

## ChatGPTからGitHubを直接編集した場合

1. 変更内容と対象ファイルを明示する。
2. 大きな変更ではブランチまたはPRを使う。
3. GitHubへの反映完了後、Codexで作業を始める前に `git pull --ff-only` する。
4. ローカルに未保存変更がある場合は、先に競合範囲を確認する。

## Codexでローカル編集した場合

1. 作業前にGitHubと同期する。
2. ファイルを編集し、リンク、PC表示、モバイル表示を検証する。
3. 変更をコミットしてpushする。
4. GitHub Pagesの公開反映を確認する。

## ブランチの使い分け

次は `main` へ直接反映してよい例です。

- 誤字修正
- お題や更新履歴の小規模追加
- 明白な表示崩れの修正

次はブランチとレビューを使います。

- 全面デザイン変更
- ページ構造やURLの変更
- 多数のお題の一括追加・改稿
- JavaScriptや外部サービスの追加
- 広告、解析、決済、フォームの導入

推奨ブランチ名：`codex/内容`、`chatgpt/内容`、`content/内容`。

## 公開前チェック

- `CNAME` が維持されている。
- 秘密情報・個人情報・非公開会話が含まれていない。
- ローカルリンクと画像参照が切れていない。
- 390px前後のスマートフォン表示で重なりや横スクロールがない。
- PC表示で余白と文字サイズが崩れていない。
- お題INDEXとアンカーが機能する。
- 生成画像の容量がWeb向けに抑えられている。

## 役割分担

- Fiore：編集長。企画、実機確認、掲載可否、収益化を含む最終判断。
- ChatGPT：コンセプト設計、言葉、ビジュアル案、運用方針、軽微なGitHub編集。
- Codex：実装、構造変更、ローカルQA、Git操作、公開確認。

## 集客と収益化

サイトはお題の本体・保管庫、SNSは入口です。まずPinterestまたはXの一つから、小さな循環を完成させます。

> 制作 → サイト掲載 → SNS用に変換 → サイトへ送客

収益化の最初の目安は月3,000円です。ただし、広告だらけのサイトや検索流入だけを狙う大量生産にはしません。作品としての本丸を人間臭く作り、告知や再編集など外へ運ぶ工程を省力化します。
